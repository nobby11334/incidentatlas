## 出典と区別

JNSA（特定非営利活動法人 日本ネットワークセキュリティ協会）の公開調査報告書の事実項目を抽出・再分類。出典は `dist/coverage.json`。報告書本文の転載は行わず、閲覧者には報告書掲載ページを案内する。

`confirmed`（確認済み）、`potential`（可能性）、`reportedCount`（確認状況未分離の調査人数）を別項目で保持。漏えい人数を合計しない。原表Aの人数を優先する。2005年No.82の表A/B不一致は明示。2014年No.1216は原表で欠番のため架空レコードを作らない。2006年折返し行は原表で補正。

`loss` は公表実額・会社費用見込・資産評価額を `lossKind` とともに保持。`modelEstimate` は原資料の当時のモデルで試算した想定損害賠償額。実額ではない。2002/2003年は千円、2004年以降は万円から円へ換算。年版によってモデルが異なる。独自シナリオ計算も別画面。モデル額は重大度判定に用いない。

重大度は独自の暫定基準。可用性影響または公表金額10億円以上L4、規模10万以上または公表金額1億円以上L3、1,000以上L2、1以上L1、情報不足は未判定。L4は停止時間・事業重要度の評価をまだ分離していないため比較には限界がある。原因分類から法的責任・過失を推定しない。

## 再取得・検証

Python標準ライブラリ、Poppler `pdftotext`、Node.jsを使用。原PDFはキャッシュしGitに含めない。

```sh
export INCIDENT_SOURCE_CACHE=/absolute/path/to/source-cache
python scripts/fetch_reports.py
python scripts/import_jnsa.py
python scripts/expand_named.py
python scripts/verify_data.py
node --check dist/app.js
node scripts/verify_yearly.cjs
```

既存の実名12件を保持し、追加事例は `scripts/expand_named.py` で管理。匿名個票の全通番と原表の件数を照合する。モデル額が抽出できない場合も0で埋めない。取得済み資料自体の誤記や事実認定の正しさを保証する検査ではない。

静的配信は `dist/`。検索、種別・業種・年・レベル・委託先・CIA・金額の絞り込み、並べ替え、50/100/200件ページ表示、条件に該当する全レコードのCSV出力、出典付詳細、分類集計、収録範囲表を搭載。毎朝8時頃（日本時間）、ChatGPTの定期タスクで新規事案・続報・過去資料を確認して更新する設定。更新の根拠と手順は OPERATIONS.md を参照。

年別グラフは調査・公表年と、発生日判明分を切替。認知・検知・和解・講演・判決・可能性の日付を発生年に代用しない。データ種類・期間を切替でき、年別表と除外件数を表示。収録不足による見かけの減少に注意。

## 2026年10月の再点検

2つの公開索引の922記録を発見情報として探索し、当事者資料URL1,150件を照合（本文取得と事故関連語確認1,031件、到達失敗45件、本文要確認74件）。組織・出典URL・公表日の照合による候補784組から、当事者本文に基づく公表記録を追加。初報・続報の統合、複数事件の分離、数値の確認／可能性／メール送信数等の個別整理も実施した。数百件分は機械照合による暫定分類であり、全項目を人手で精査済みという意味ではない。原文で同値を確認できない数量は採用しない。本文中の情報項目リストは対象外の語を含む場合があり、その旨を明記。

この784組の整理結果は、10月の登録697件と確認待ち87組。名称やURL・日付の違いによる重複、同じサービス提供元事故の波及先、同日公表の別事故等の完全な統合・分離は未完了。国内全件の収録率や独立事故総数ではない。照合状況・出典・確認待ちは dist/october-2026-audit.json 。

主な個別訂正：ニフティの対象上限は続報で18,000件、GMOリサーチ&AIの持ち出し確認894,082件と不正ポイント交換2,869,500円を分離、ブックオフの6,427,735件と6,383,279人を区別。日本経済新聞のWorkspace/M365/開発クラウドを別事案に分離。ローソンの70万件のメール送信をID流出人数にしない。メドレーの787医療機関を漏えい人数にしない。

全期間の照合状況は `dist/source-manifest.json`、全候補・未解消理由は `dist/reconciliation.json` に保存しています。JNSAの匿名歴史個票に加え、2024年12月以降の公表アーカイブと複数の索引を原資料URLで照合しています。索引は発見にのみ利用し、本文の要約は転載しません。公表記録には続報・関連公表が含まれ、独立事故数とは一致しません。国内の完全網羅は未達です。日次の更新と遡及収集の手順は OPERATIONS.md を参照してください。

## β版の公開方針

初期画面は公表記録・匿名歴史資料・一次資料本文の確認待ち候補をすべて表示し、確認段階をラベルで区別します。「精査前」「匿名・歴史資料」「すべて」は独立した選択肢です。個別整理は全項目の確認完了を意味しません。精査前の記録は被害有無・分類・数量の意味を未精査として表示し、攻撃分類・レベルの確定表示や数量の試算転記を抑止します。年別グラフも確認段階を選択でき、発生日が不明な場合に公表日で埋めません。

訂正窓口は [GitHub Issues](https://github.com/nobby11334/incidentatlas/issues/new)。対象ID・公開一次資料・修正箇所を記載してください。投稿は公開されるため、漏えいデータや認証情報、個人情報は投稿しないでください。告知では「公開資料を整理する継続更新中のβ版」と説明し、収録レコード数を国内の事故総数と表現しないでください。


## GitHub Pagesへの初回公開と日次反映

公開元：`main`の`dist/`。Settings → Pages → Build and deployment → Sourceで **GitHub Actions** を選択してください。workflowは用意済みです。mainへの更新またはActions画面のRun workflowで検証・公開が実行されます。初回設定前の失敗実行はRe-run failed jobsで再開できます。

日々の情報収集は既存のChatGPT定期タスクが担当し、新規・続報・訂正を検証してmainへ反映。Pages workflowはそのpushを受けてサイトを更新します。公開時に生成する `deployment.json` のsourceCommitとデータハッシュで配信内容を確認できます。収録情報に変化がない日は日付だけを変更しません。


2026-11-07の一次資料再取得で実名公表記録を1,330件追加。確認待ち資料は2,836から1,304へ減少しました。追加分は主に2025～2026年で、2019～2023年等の収録不足は継続しています。既知の確認待ち資料は毎朝7時30分頃にGitHub Actionsで再取得し、毎朝8時頃の情報探索タスクでは新規公表元や過去分も探索します。


一覧の初期表示は全収録記録とし、公表記録・調査個票17,729に、一次資料本文の確認待ち探索候補1,304を加えた19,033レコードを表示します。探索候補は一次資料未確認と明示し、事故数のグラフから除外します。既知3情報源の外や過去年代の未探索分が残り、検索可能な国内公表全体を網羅した状態ではありません。配信時は内容ハッシュ付きのJS・CSS・JSONを用い、HTMLと古いプログラム・データの版混在を防ぎます。
